Contributions to both [`theaver-frontend`](https://github.com/MootSasa/theaver-frontend) and [`theaver-website`](https://github.com/MootSasa/theaver-website) are welcome through Pull Requests.

## Branch & commit conventions

- Never commit directly to `main` or `beta`. Always open a topic branch:
  - `feat/<name>` for new features
  - `fix/<name>` for bug fixes
  - `refactor/<name>` for internal cleanups
  - `docs/<name>` for documentation updates
- Write commit subjects in English following **Conventional Commits** (`feat(chat): ...`, `fix(notifications): ...`).

## Pre-PR verification

Before opening a Pull Request in `theaver-frontend`, verify static analysis and widget/unit tests:

```bash
flutter analyze
flutter test
```

For documentation and site changes in `theaver-website`:

```bash
npm run check
npm run build
```

## Writing user-facing changelog entries

Release notes displayed on GitHub Releases, inside the in-app updater dialog, and on `/changelog` are written for end users rather than git commit logs:

1. **Describe the visible effect:** Explain what improved for the person using the app instead of naming internal widgets, refactors, or file paths.
2. **Group by feature:** Collapse multi-commit feature work into 1–3 concise bullet points.
3. **Omit internal churn:** Skip CI fixes, version bumps, test-only commits, and regressions fixed before release.
4. **Use standard sections:** Organize entries under **Added**, **Improved**, **Fixed**, and **Security**.
