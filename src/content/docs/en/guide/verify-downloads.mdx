If you downloaded an installer manually, you can check before opening it that the file was not modified in transit. Every official release includes a checksum and a digital signature.

<SignatureVerifyDiagram locale="en" />

## Public signing keys

Both keys are hosted on this site and mirrored in the open-source [`theaver-frontend`](https://github.com/MootSasa/theaver-frontend) repository under `signing/`:

- Linux GPG release public key: [`/signing/theaver-release-public.asc`](/signing/theaver-release-public.asc)
- Windows code-signing root certificate: [`/signing/theaver-windows-root.cer`](/signing/theaver-windows-root.cer)

## Checking SHA-256 checksums

Each download on [Downloads](/downloads) and in the in-app update sheet displays its exact `SHA-256` hash. Compute the local hash and compare both strings:

<CodeTabs tabs={['Linux / macOS', 'Windows (PowerShell)']}>
```bash
shasum -a 256 theaver-v1.20.3-beta-linux-x64.tar.gz
# or on Linux:
sha256sum theaver-v1.20.3-beta-linux-x64.tar.gz
```

```powershell
Get-FileHash .\theaver-v1.20.3-beta-windows-x64-setup.exe -Algorithm SHA256
```
</CodeTabs>

## Verifying Linux archives with GPG

Each `.tar.gz` archive ships alongside a matching `.tar.gz.asc` signature file:

```bash
curl -fsSLO https://theaver.app/signing/theaver-release-public.asc
gpg --import theaver-release-public.asc
gpg --verify theaver-v1.20.3-beta-linux-x64.tar.gz.asc theaver-v1.20.3-beta-linux-x64.tar.gz
```

Look for `Good signature` from the imported Theaver release key.

## Verifying Windows installers

Windows installers and binaries are signed with Authenticode. To inspect the signature locally:

```powershell
curl -fsSLO https://theaver.app/signing/theaver-windows-root.cer
Get-AuthenticodeSignature .\theaver-v1.20.3-beta-windows-x64-setup.exe
```

<Callout type="warning" title="Stick to official download sources">
  Only download installers from `theaver.app`, `storage.theaver.app`, or the official GitHub Releases page (`MootSasa/theaver-frontend`).
</Callout>
