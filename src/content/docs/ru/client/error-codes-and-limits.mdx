Все ошибки REST API и WebSocket RPC используют единую структуру ответа и символьный код `error` в верхнем регистре, чтобы клиент не разбирал текстовые описания.

## Единый формат ответа об ошибке

```json
{
  "ok": false,
  "success": false,
  "error_code": 429,
  "error": "FLOOD_WAIT",
  "description": "Rate limit exceeded. Retry in 14 seconds.",
  "message": "Rate limit exceeded. Retry in 14 seconds.",
  "parameters": {
    "retry_after": 14
  },
  "retry_after": 14
}
```

При HTTP `429` сервер дополнительно выставляет стандартный заголовок `Retry-After`.

## Таблица кодов ошибок

| HTTP-статус | `error` | Причина и действие клиента |
|---|---|---|
| `400` | `BAD_REQUEST` | Некорректные параметры или формат запроса |
| `400` / `401` | `API_ID_INVALID` | Неверный, несуществующий или отозванный `X-Api-Id` |
| `401` | `API_HASH_INVALID` | Пропущен или неверен `X-Api-Hash` для кастомного `api_id >= 100000` |
| `401` | `UNAUTHORIZED` | Токен отсутствует, истёк или имеет неподходящий `scope` |
| `401` | `SESSION_REVOKED` | Сессия завершена удалённо; очистите токен и покажите экран входа |
| `401` | `TWO_FACTOR_REQUIRED` | Требуется облачный пароль 2FA для завершения входа |
| `403` | `FORBIDDEN` | Недостаточно прав доступа |
| `403` | `CHAT_WRITE_FORBIDDEN` | Нет прав на отправку сообщений или действует мут |
| `403` | `CHAT_FORWARDS_RESTRICTED` | В чате или канале запрещена пересылка контента |
| `403` | `USER_PRIVACY_RESTRICTED` | Ограничено настройками приватности получателя |
| `403` | `USER_IS_BLOCKED` | Отправитель заблокирован пользователем |
| `404` | `NOT_FOUND` | Сущность, чат, сообщение или инвайт не найдены |
| `409` | `CONFLICT` / `USERNAME_OCCUPIED` | Конфликт состояния или занятый username |
| `429` | `FLOOD_WAIT` | Превышен лимит запросов (по IP, auth или `api_id`) |
| `429` | `SLOWMODE_WAIT` | Включён медленный режим чата; подождите `parameters.retry_after` сек |
| `400` / `500` | `UNKNOWN_METHOD` / `INTERNAL_ERROR` | Неизвестный RPC `type` или внутренняя ошибка |
| `503` | `SERVICE_UNAVAILABLE` | Временная перегрузка хранилища или воркеров |

## Квоты `api_id` и стратегия повторов

- Каждое новое приложение (`api_id >= 100000`) получает квоту по умолчанию **`600 RPM`** в скользящем окне плюс отдельные антиспам-ограничения на публичные эндпоинты `/api/auth/*`.
- **Обработка `429`:** прочитайте `parameters.retry_after` (или заголовок `Retry-After`), поставьте повторную отправку для этого чата/метода на паузу на `retry_after + 0.25с` и никогда не повторяйте запросы в жёстком цикле.
- При `401 SESSION_REVOKED` сразу сбрасывайте локальную сессию — не пытайтесь обновлять токен через `/api/auth/refresh`.
