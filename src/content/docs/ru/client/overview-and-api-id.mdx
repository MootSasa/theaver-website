Theaver открывает публичный клиентский протокол: сторонние десктопные, мобильные, CLI- и веб-клиенты работают через те же самые маршруты HTTPS REST и WebSocket RPC, что и официальные приложения.

## Базовые точки входа

| Поверхность | Адрес | Транспорт |
|---|---|---|
| Клиентский REST API | `https://api.theaver.app/api/*` | HTTPS JSON и multipart |
| WebSocket RPC в реальном времени | `wss://api.theaver.app/api/ws` | Постоянный WebSocket (JSON-фреймы) |
| Защищённые медиа и аватары | `https://api.theaver.app/api/files/download/*` | HTTPS с Bearer JWT или `?mt=` HMAC-тикетом |
| Машиночитаемая схема | [`/openapi.json`](/openapi.json) | OpenAPI 3.1.0 JSON |

<Callout type="info" title="30-битные Feistel ID сущностей">
  Идентификаторы пользователей, чатов, каналов, вложений, папок и опросов лежат в диапазоне `100 000 000` – `2 147 483 647` (безопасный 32-битный signed integer). Они не последовательны — никогда не перебирайте ID инкрементом.
</Callout>

## Ключи клиента: `api_id` и `api_hash`

Сторонний клиент идентифицирует себя парой ключей, которую можно выпустить одним из двух способов:

1. **Веб-консоль разработчика:** [Консоль приложений (`/ru/developers/apps`)](/ru/developers/apps) (вход по email-коду или QR).
2. **Студия ботов и клиентов:** команда `/newclient` в диалоге с **`@BotMother`** или вкладка **Client Apps** в его Mini App.

Один аккаунт может держать до **10 активных кастомных приложений** (`api_id >= 100000`), а слоты `1..6` зарезервированы за официальными клиентами:

| `X-Api-Id` | Платформа / владелец | Примечание |
|---|---|---|
| `1` | Официальный Android-клиент | Системный слот |
| `2` | Официальный iOS-клиент | Системный слот |
| `3` | Официальный Windows-клиент | Системный слот |
| `4` | Официальный macOS-клиент | Системный слот |
| `5` | Официальный Linux-клиент | Системный слот |
| `6` | Официальный Web-клиент (`app.theaver.app`) | Системный слот |
| `>= 100000` | Кастомный или личный клиент | Требует `X-Api-Hash` на шагах авторизации; лимит `600 RPM` |

### Правила проверки заголовков

- Передавайте `X-Api-Id` и `X-Api-Hash` (64 hex-символа; секрет показывается **один раз** при создании или ротации) на маршрутах авторизации (`/api/auth/register/*`, `/api/auth/login`, `/api/auth/qr/*`, `/api/auth/oauth/*`).
- Созданная сессия запоминает `api_app_id`, поэтому в **Настройки → Устройства** пользователь видит название вашего клиента, платформу и автора.
- Неизвестный или отозванный `X-Api-Id` возвращает `400`/`401` `API_ID_INVALID`. Неверный секрет для кастомного ID возвращает `401` `API_HASH_INVALID`.
- Если `X-Api-Id` на общих вызовах не указан, сервер подставляет официальный клиент по умолчанию, но кастомные клиенты `api_id >= 100000` обязаны отправлять валидный `X-Api-Hash`.

## Рекомендуемые заголовки устройства

Отправляйте стабильные метаданные устройства в каждом запросе авторизации и REST API:

```http
Authorization: Bearer <jwt_token>
X-Api-Id: 100420
X-Api-Hash: 4f9a7d...64_hex_chars
X-Device-ID: my-client-device-uuid-v4
X-Device-Name: Acme CLI 1.0 (ThinkPad X1)
X-Device-Type: cli
X-OS-Name: Linux
X-OS-Version: 6.12
X-App-Version: 1.0.0
X-App-Locale: ru
```

Допустимые значения `X-Device-Type`: `android`, `ios`, `windows`, `macos`, `linux`, `web`, `desktop`, `cli`, `other`. Токен консоли разработчика имеет `scope: "developer_portal"` и отклоняется клиентскими маршрутами с кодом `401`.
