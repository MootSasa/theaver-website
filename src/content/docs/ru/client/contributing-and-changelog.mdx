Pull Request принимаются в оба открытых репозитория: [`theaver-frontend`](https://github.com/MootSasa/theaver-frontend) и [`theaver-website`](https://github.com/MootSasa/theaver-website).

## Ветки и коммиты

Не коммитьте напрямую в `main` или `beta`. Создавайте тематическую ветку (`feat/<name>`, `fix/<name>`, `refactor/<name>`, `chore/<name>`, `docs/<name>`), а заголовки коммитов пишите на английском языке по формату **Conventional Commits** (`feat(chat): ...`, `fix(notifications): ...`).

## Проверки перед Pull Request

Для клиента в `theaver-frontend`:

```bash
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
python3 scripts/calculate_release.py --validate-fragments
```

Для сайта и документации в `theaver-website`:

```bash
npm run check
npm run build
```

## Двуязычные фрагменты Changelog

Заметки для GitHub Releases, диалога обновления в клиенте, push-уведомлений и страницы [`/ru/changelog`](/ru/changelog) собираются из отдельных файлов в `changelogs/fragments/<topic-slug>.md`, а не из сырого списка коммитов.

В заголовке файла указываются `type` (`added`, `improved`, `fixed` или `security`), однострочные `summary_ru` и `summary_en` без Markdown, а ниже идут списки изменений в блоках `### ru` и `### en`:

1. **Описывайте видимый результат:** формулируйте, что изменилось для пользователя, без названий внутренних виджетов, путей к файлам и SHA-хэшей.
2. **Сжимайте серию коммитов:** несколько коммитов одной задачи объединяйте в 1–3 коротких пункта на каждом языке.
3. **Убирайте технический шум:** для тестов, правок CI, рефакторинга и документации фрагмент не нужен — укажите `[no-changelog]` в описании PR.
