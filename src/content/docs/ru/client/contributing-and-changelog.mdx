Мы принимаем Pull Request в публичные репозитории [`theaver-frontend`](https://github.com/MootSasa/theaver-frontend) и [`theaver-website`](https://github.com/MootSasa/theaver-website).

## Ветки и коммиты

- Не коммитьте напрямую в `main` или `beta`. Создавайте тематическую ветку:
  - `feat/<name>` для новой функциональности
  - `fix/<name>` для исправлений
  - `refactor/<name>` для рефакторинга
  - `docs/<name>` для правок документации
- Сообщения коммитов пишутся на английском языке по формату **Conventional Commits** (`feat(chat): ...`, `fix(notifications): ...`).

## Проверка перед Pull Request

Для клиента в `theaver-frontend`:

```bash
flutter analyze
flutter test
```

Для сайта и документации в `theaver-website`:

```bash
npm run check
npm run build
```

## Правила составления записей Changelog

Описания релизов на GitHub, в окне обновления клиента и на странице `/ru/changelog` ориентированы на пользователей, а не на внутренние детали реализации:

1. **Описывайте видимый результат:** формулируйте, что улучшилось для человека, без названий внутренних виджетов и файлов.
2. **Объединяйте по смыслу:** несколько коммитов одной задачи сжимайте в 1–3 ясных пункта.
3. **Исключайте технический шум:** не включайте правки CI, бамп версий, тесты и починку регрессий внутри незавершённой ветки.
4. **Структурируйте по разделам:** группируйте изменения в блоки **Новое**, **Улучшения**, **Исправления** и **Безопасность**.
